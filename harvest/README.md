# TaskbarHero 收菜助手

作者：**TheFallen**

ZIP 便携包的使用方式：将包内整个 `harvest` 文件夹解压到游戏安装目录，与 `TaskBarHero.exe` 放在同一级，然后双击 `harvest/Start.cmd`。便携包已附带 Python 和 Tkinter，无需另行安装 Python；仍使用系统的 Windows 简体中文 OCR。不要在 ZIP 内直接启动。
更新已校准的安装时保留目标电脑原有的 `harvest/config.json`，替换程序文件时不要覆盖它。

源码版双击 `Start.cmd` 启动，使用本机 Python、Tkinter 和 Windows 简体中文 OCR，无 pip 依赖。有随包 `runtime` 目录时优先使用随包运行环境。

多开时点击一次“开始收菜”，助手会按进程 PID 从小到大依次处理当前已打开的所有游戏实例。本轮首次进入每个进程（包括第一个）时，确认窗口激活后按一次空格，松开并等待后再检查页面、开始收菜；暂停续跑或同一进程失焦恢复不会重复按空格。各窗口使用相同的校准与勾选设置，窗口尺寸、界面缩放和面板布局需一致；窗口在桌面上的位置可以不同。
多开收菜时先保存各队列窗口的位置和显示状态，处理当前进程时临时最小化其余队列窗口，防止透明区域截入其他游戏的战斗栏或页面。切换到下一个进程前恢复该窗口，再激活并收菜。整轮结束、按 F10 或任务异常退出时尝试恢复各窗口原来的位置、最小化及最大化状态；自动收菜的等待期间也恢复。本轮暂停时保留当前隔离状态，确认继续后在截图或输入前再次检查其他窗口；恢复失败会记录具体 PID 并提示手动还原。
支持普通窗口标题 `TaskBarHero` 以及 Sandboxie 标题 `[#] TaskBarHero [#]`，仍核对游戏可执行文件路径，每个 PID 只处理一次。
支持默认 Sandboxie 复制路径 `X:\Sandbox\用户名\沙盒名\drive\盘符\原游戏路径`，将其映射回原盘符和完整游戏目录后比较，可将普通实例与不同沙盒内同一安装的实例一同加入队列。

Sandboxie 多开时，助手请在沙盒外运行。任务管理器显示的 `TaskBarHero.exe` 总数可能大于当前桌面可操作窗口数：沙盒可能拒绝进程路径查询，其他 Windows 会话或桌面的窗口也不一定能枚举。点击“多开诊断”，或双击 `Diagnose.cmd`，可只读检查每个 PID 未加入队列的原因；报告保存在 `process-diagnostics.txt`，每次覆盖旧报告。若明确显示错误 5（访问被拒绝），可在沙盒外以管理员运行助手后重试；仍被隔离的实例不能靠添加 PID 强行控制。不同会话需在对应会话内运行助手。

点击“自动收菜”立即执行同样的一轮多开收菜；整轮完成后等待“自动间隔（分钟）”再自动开始下一轮，默认 30 分钟，可设为 1～1440 分钟并自动保存。每轮重新枚举游戏进程，沿用当前校准及勾选。等待时显示倒计时，修改间隔会按上轮完成时刻重新计算。助手需保持运行；按 F10、停止按钮或“停止自动收菜”会取消本轮和后续循环，关闭助手也会停止，重开后需再次点击开启。

处理规则：

- 识别到“瘟疫之果”时，不限品质、无视腐蚀勾选，优先 Alt＋右键放入魔方腐蚀；不会因其高品质而入库。名称必须在物品标题中确认，支持本次截图中的像素文字图像；只在描述中提到名称不算。锁定物品保留；数量不明时只添加一次。
- 铭刻材料独立于雕刻材料：普通、罕见、稀有品质优先 Alt＋右键放入魔方腐蚀；其余已确认品质（传奇、不朽、至宝、奥秘、超凡、天界、神圣、宇宙）优先 Ctrl＋右键入库。此规则不受腐蚀勾选影响；锁定物品、品质或类型冲突仍保留，低品质腐蚀数量不明时只添加一次，高品质入库不要求读取数量。
- “腐蚀范围”分装备、材料两行，普通、罕见、稀有、传奇、不朽可以分别勾选。除瘟疫之果外，至宝、超凡、天界、神圣、宇宙五种品质自动优先 Ctrl＋右键入库。制作材料、装饰材料、雕刻材料统一按“材料”的品质勾选处理；铭刻材料使用上一条专门规则。
- 从 1.8 升级时，将旧三类材料已勾选的品质取并集合并；装备勾选不变。全新配置默认勾选普通、罕见、稀有装备，以及普通至不朽的材料。旧点位、界面校准和等待时间保留，勾选项随开始收菜或保存校准写入配置。
- 供奉材料识别后优先 Ctrl＋右键入库，不受腐蚀勾选影响；已锁定物品始终保留。材料必须识别出独立类型行，可以是“供奉材料”、材料名称或“材料”；描述里仅提及材料不算类型证据。兼容类型图标被 OCR 读成“0”等已观察到的情况。装饰、铭刻材料支持只在当前提示框头部识别完整类型字形；罕见、稀有品质支持头部字形识别，与 OCR 品质冲突时仍保留。
- 腐蚀循环结束后检查背包剩余的传奇、不朽装备，各按同品质每 9 件合成，不混放两个品质，也不要求同等级。勾选了对应装备品质的腐蚀时仍优先腐蚀；要保留用于合成，请取消该装备品质的腐蚀勾选。清空全部腐蚀勾选不会关闭合成。
- 背包物品通过 Alt＋右键添加到魔方，不再拖入。已添加的材料仍会复核背包或魔方数量；每次腐蚀只认可确认的实际消耗。
- 合成完成后普通右键点击九宫格中间的产物，收回背包，确认九宫格清空后整理重扫。传奇合成产出的不朽装备也可补足下一批；直到不足同品质 9 件，或达到“合成最多批数”。
- 执行开始时检查魔方、仓库和背包页面；全部隐藏且识别到展开按钮时先展开，再识别对应按钮补开缺失页面，确认打开后先整理一次背包，再开始扫描。已有页面不重复点击。
- 展开或收起按钮出现多个候选时，优先对照本轮前一个进程已确认的按钮位置，并通过悬停核对当前窗口归属；窗口尺寸和布局仍需与校准一致。悬停检查只移动鼠标，点击前继续核验实际接收输入的窗口。首次处理没有位置记录时，仅在归属检查后剩一个候选才点击；仍无法唯一确认则保存游戏截图和候选坐标。按钮位置记录只在本轮队列内传递，不修改配置或跨轮沿用。
- 多开时逐个完成入库、腐蚀和合成，再尝试收起全部页面；最后一个进程也会尝试收起。收菜已完成但收起按钮重试后仍无法唯一识别时，保存截图、保留当前页面并继续队列；实际点击后收起结果未确认仍暂停处理。每个进程独立使用“合成最多批数”，日志显示当前序号、总数和 PID，运行记录分别保存到带 `-pid进程号` 的目录。F10 会停止整队任务。
- 扫描背包全部 15 行、105 格；窗口每次显示 3 行，自动在背包区域滚轮向下查找。指定高品质物品和供奉材料先尝试入库当前页；满页无法接收时依次切换下一页，最后一页也满后从第一页复查，全部页面均无法接收则保留并跳过该物品，继续收菜。
- Ctrl＋右键入库支持与仓库已有物品堆叠，不要求先找到空格；仍要求背包原格清空、当前仓库物品图像或右下角数量变化、魔方已有槽位保持不变。确认仓库连续三帧稳定，或确认已变化且匹配来源图标的接收格连续三帧稳定，避免其他仓库格的动画阻断确认。
- 常规腐蚀要求品质、类型明确；瘟疫之果按名称独立确认。已确认腐蚀但堆叠数量不明的材料只添加一次；数量明确时按数量逐次添加。合成要求明确为未锁定的传奇或不朽装备，缺失等级不影响合成。其他指定五种高品质只要品质明确且未锁定，即可整格入库，不要求识别具体类型或数量。供奉材料按独立类型行确认后入库，不要求识别品质或堆叠数量；仅在描述中提到“供奉”时保留。
- 每轮结束后只保留最近一轮全部进程的记录，自动清理更早的运行目录；未产生新记录时保留原记录。自动清理不修改校准、设置、模板或游戏数据。
- 游戏短暂失去前台焦点时自动重新激活当前 PID；恢复后确认窗口、尺寸和点击位置，再继续任务。15 秒内最多尝试 3 次，持续失焦则暂停并提示切回游戏后确认。F10 可随时停止。

## 首次校准

1. 打开游戏的背包、仓库、魔方三个面板。保持窗口和界面缩放不变。
2. 在助手的“窗口校准”页点击“截取窗口（3 秒后）”。截图期间助手隐藏。
3. 左侧选择点位，在截图上点击。背包设置为 7 列、可见 3 行、总共 15 行。背包坐标仍只标记可见区域：第一行第一格中心和第三行最后一格中心；不要把“可见行数”改成 15。仓库行列数按实际填写。
4. 区域按左上、右下两次点击框选：功能文字、两种模式的复选框、合成等级配方。范围只包含对应控件，避免动画、金钱数字和物品。
5. 功能菜单的两个选项需要截图时展开：点击截取后，在 3 秒内手动展开游戏的功能菜单，再在截图中标记选项。截图不必显示全部点位；每次截图会保留已设点位。
6. 腐蚀模式：清空魔方、取消“包含仓库物品”，勾选助手中的对应状态，点击“记住当前腐蚀界面”。
7. 合成模式：清空魔方、取消“包含仓库物品”，选好平时使用的配方和固定等级设置，点击“记住当前合成界面”。标记的仓库空格必须确实为空。
8. 保存。修改任意点位后，需要重新记住两个界面。

当前版本保持记录的配方，不会自动切换 Lv.80～90 等等级配方。背包自动滚动扫描；仓库满页时自动翻页和复查，无需新增校准点。

## 每次收菜

1. 保持所有待处理游戏的窗口尺寸、界面缩放及面板布局与校准时一致，魔方九宫格为空。仓库需有足够容量，可以是空格，也可以是已有同物品堆叠的余量。页面可以全部收起，执行时会先点击展开按钮，再自动打开缺失的魔方、仓库和背包页面。
2. 勾选“腐蚀范围”，点击“开始收菜（边扫边执行）”。助手获取本次游戏进程列表，按 PID 顺序逐个切换。每个游戏先整理背包，再向上滚到背包顶部，逐格识别并立即处理符合条件的物品；供奉材料和指定五种高品质优先入库，腐蚀目标九格满批或扫描结束后执行。可见三行读满后，通过相邻行图像重叠确认向下滚动距离，只读取新出现的行，最多读到第 105 格。
3. 执行时清单实时显示识别结果，点击清单行可查看 OCR 原文。“测试第一格”可用于只读检查悬停，不消耗物品。`runs/时间/` 中保留每次截图、清单和事件记录。像素字体可能识别不清，未识别物品会保留。
4. 每批腐蚀完成后整理背包，从顶部继续识别，直到没有符合勾选的腐蚀目标。随后检查剩余传奇、不朽装备，同品质凑齐 9 件后切换合成页面，Alt＋右键逐件放入，满 9 件才点击合成。产物在中间格出现后普通右键收回背包，再整理重扫；不足 9 件保留。当前进程完成后自动收起全部页面，确认后再处理下一个。暂停提示点击“确定”继续当前进程的当前阶段；按 F10 或停止按钮终止整队任务。

## 补充物品与配置

在“补充物品与配置”页填写提示框里的完整物品名称，选择装备或材料、腐蚀或入库，再选择品质范围或全部品质，点击新增规则。也可从当前识别清单预填，核对后保存。匹配采用完整名称，名称补读要求两次一致；不会用相似名称或描述猜测。补充规则优先于默认规则，锁定、已装备对比及识别冲突仍保留。

选中规则后可载入修改。删除支持单选、Ctrl 多选、Shift 连选或全选删除。规则保存在本机 config.json；清理缓存不会删除规则。

导出配置始终包含常规设置，可分别选择是否包含窗口校准和补充物品。窗口校准包含窗口尺寸、行列数、点位、区域和已记录界面。导入会替换勾选且文件包含的部分；补充物品是替换全部规则，不是追加。跨电脑导入时可以不选窗口校准，保留目标电脑自己的校准。导入不会自动开启收菜。

## 数量与物品处理

制作、装饰、雕刻材料统一使用“材料”品质勾选。铭刻材料独立处理：普通、罕见、稀有腐蚀，其他已确认品质入库。瘟疫之果不论品质腐蚀；供奉材料入库。指定高品质物品优先入库，补充规则可覆盖默认处理。

已确认腐蚀目标且数量明确时，按数量发送 Alt＋右键，每次确认魔方新增一格；材料数量未确认时只添加一次，执行后整理重扫。魔方格子不足时先执行本批。添加结果异常则跳过该物品。已加入魔方的物品通过普通右键取回。

装备等级读不清不影响同品质九件合成；传奇与不朽不混放。腐蚀勾选包含传奇或不朽装备时，优先按腐蚀勾选处理；若希望保留用于合成，应取消对应装备品质的腐蚀勾选。

## 多开与故障排查

助手应在游戏所在的交互桌面运行。多开按同一游戏完整安装路径核对，默认 Sandboxie 路径会还原到原安装目录；自定义沙盒存储结构需另外适配。点“多开诊断”或运行 Diagnose.cmd 生成本机进程报告，包含每个 PID 的路径、会话、窗口及访问失败原因。诊断不会激活游戏或发送输入。

运行中避免手动抢占鼠标或前台焦点。多开任务会临时最小化其他队列实例，在本轮结束、停止或异常退出后恢复原窗口状态。暂停提示点确定会继续当前任务，F10 或停止按钮终止整个队列。

提示框远离物品或被屏幕截断时，先尝试匹配来源物品图标。确认异常后，通过设置 → 图形 → 恢复窗口位置 → 关闭设置恢复面板布局，再重新定位继续任务。持续异常不会每格反复触发恢复。系统显示分辨率与远程画面的视觉大小可能不同；更改窗口尺寸或游戏缩放后请重新校准。

“测试第一格”只读悬停识别。运行记录位于 runs，保存截图、OCR 原文、清单和事件；每轮结束后只保留最近一轮的所有实例记录。“清理缓存”在空闲时删除运行记录、错误日志和 Python 字节码，保留配置、补充规则、识别模板、测试样本和游戏数据。

像素字体可能漏读；类型或品质冲突、名称不一致等无法确认的物品会保留。识别与动作验证的自动测试使用图片和模拟输入，不能代替目标电脑上的实际校准及测试。

## 源码和打包

参见仓库根目录 README.md 的测试和构建命令。公开源码仅提供空白默认配置 config.example.json，不附带个人校准、补充规则或运行记录。部分历史 check_*.py 回放脚本需要本机保留的旧记录；日常回归使用 unittest 测试集。
